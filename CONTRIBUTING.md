describes how you can participate and is intended to be straightforward,
transparent, and free of unnecessary legal overhead.

## How to Contribute

The preferred way to contribute is through an open pull request against the
repository. Contributions of all kinds are welcome, including bug fixes,
new features, documentation, and improvements to existing tests.

### Before You Start

1. Check the existing issues and pull requests to avoid duplicating work.
2. Discuss substantial changes or new features before implementing them.
3. Review the project's coding conventions and existing code for style.

### Opening a Pull Request

1. Fork the repository and create a topic branch from the main branch.
2. Make focused, well-scoped changes with clear commit messages.
3. Keep the change minimal and easy to review.
4. Update or add tests to cover your changes where applicable.
5. Ensure your branch is up to date with the upstream main branch.

### Build and Test Requirement

Every contribution must build successfully and pass the existing test
suite before it is merged. Please run the build and tests locally and
confirm they pass.

- Configure and build the project using CMake.
- Run the full test suite and verify there are no failures.
- Fix any build errors, test failures, or warnings introduced by your
  change before submitting the pull request.

## Reporting Issues

If you find a bug, please open an issue with a clear description, the
steps to reproduce it, and the expected versus actual behavior.

## Code of Conduct

Be respectful and considerate toward all contributors. Harassment,
discrimination, or disruptive behavior is not tolerated.

## Questions

If you have questions about contributing, please open an issue and the
maintainers will respond.
